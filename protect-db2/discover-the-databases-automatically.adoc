= 使用 SnapCenter 自動探索 IBM Db2 資料庫
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
資源是由 SnapCenter 管理的 Linux 主機上的 IBM DB2 資料庫。您可以在探索可用的 IBM DB2 資料庫之後、將資源新增至資源群組、以執行資料保護作業。

.開始之前
* 您必須已完成安裝 SnapCenter 伺服器、新增主機及設定儲存系統連線等工作。
* SnapCenter IBM Db2 外掛程式不支援自動探索 RDM/VMDK 虛擬環境中的資源。您必須在手動新增資料庫時提供虛擬環境的儲存設備資訊。詳情請參閱 <<resources_rdm_vmdk_virtual_environments,駐留在 RDM/VMDK 虛擬環境中的資源>>。


.關於這項工作
* 安裝外掛程式之後、系統會自動探索該 Linux 主機上的所有資料庫、並顯示在「資源」頁面上。
* 只會自動探索資料庫。


無法修改或刪除自動探索的資源。

.步驟
. 在左導覽窗格中、按一下 * 資源 * 、然後從清單中選取 IBM DB2 的外掛程式。
. 在「資源」頁面中、從「檢視」清單中選取資源類型。
. （選用）按一下 * *image:../media/filter_icon.gif["篩選圖示"]、然後選取主機名稱。
+
然後按一下 *image:../media/filter_icon.gif["篩選圖示"]即可關閉篩選窗格。

. 按一下*重新整理資源*以探索主機上可用的資源。
+
這些資源會連同資源類型、主機名稱、相關資源群組、備份類型、原則和整體狀態等資訊一起顯示。

+
** 如果資料庫位於NetApp儲存設備上且未受到保護、則「整體狀態」欄中會顯示「未受保護」。
** 如果資料庫位於NetApp儲存系統上且受到保護、且未執行備份作業、則「整體狀態」欄中會顯示「未執行備份」。否則狀態會變更為「備份失敗」或「備份成功」、視上次的備份狀態而定。





IMPORTANT: 如果資料庫重新命名為SnapCenter 不屬於支援範圍、您必須重新整理資源。

[[resources_rdm_vmdk_virtual_environments]]
.駐留在 RDM/VMDK 虛擬環境中的資源
駐留在 RDM/VMDK 虛擬環境中的資源無法自動探索。您必須停用自動探索，並為 IBM Db2 的 SnapCenter 外掛程式手動新增執行個體，如下所示：

[listing]
----
Set-SmConfigSettings -Agent -Hostname <HOST_NAME> -configSettings @{"DISABLE_AUTO_DISCOVERY"="true"}

PS C:\> Add-SmResource -HostName 10.32.212.13 -PluginCode DB2 -ResourceType Instance -ResourceName db2inst1 -StorageFootPrint
(@{"VolumeName"="windb201_data01";"LUNName"="windb201_data01";"StorageSystem"="windb2svm"})
----
如需詳細資訊，請參閱 link:back-up-db2-databases.html["備份 IBM Db2 資料庫，PowerShell cmdlets"]。
